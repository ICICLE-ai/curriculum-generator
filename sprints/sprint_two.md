# Sprint Two - Verification and Model Validation

## Overview

Following the successful deployment of the AI pipeline across multiple domains on the Ohio Supercomputer Center (OSC), the primary goal of Sprint Two shifts from operational execution ("can it run?") to output dependability ("can we trust its outputs and learning alignment?"). This sprint focuses on validating model accuracy, debugging prediction mismatches, and establishing robust reporting to ensure the pipeline acts as a polished, reliable curriculum tool.

## Objectives & Action Items

### 1. Schema & Semantics Verification

- **Verify Column Definitions:** Clarify the exact semantic meaning of the `predicted_class` column in the generated CSVs. Determine whether it represents a raw DINOv2 classification, a VLM-generated answer, or a mapped curriculum label.
- **Stabilize Output Schema:** Ensure the output CSV structure is robust enough to act as the foundation for downstream curriculum design.

### 2. Error Analysis & Mismatch Inspection

- **Skin Cancer Dataset (69.2% Agreement):** Manually inspect a random sample of mismatches. Determine if the errors originate from the vision backbone, the VQA prompt constraints, label mapping inconsistencies, or the source data itself.
- **Hurricane Dataset (89.0% Agreement):** Analyze the 11 mismatches (out of 100) to understand edge-case failures in the satellite imagery domain.
- **Rock-Paper-Scissors Dataset (100% Agreement):** Acknowledge the 5-row run as a successful smoke-test, but prepare it for the scaled validation pass.

### 3. Automated Reporting & Run Summaries

- **Run Summary Artifacts:** Update the pipeline to automatically generate a `run_summary.json` or `.txt` file for each experiment. This summary must include:
  - Total rows processed
  - Accuracy / Label agreement percentages
  - Class balance
  - Total runtime
  - Error counts by class

### 4. Second Validation Pass

- **Scale Up Validation Runs:** Execute a second validation pass on slightly larger, but manageable samples across all datasets.
- **Cross-Dataset Error Comparison:** Compare error patterns holistically across the datasets (rather than just raw accuracy numbers) to identify systemic pipeline issues versus domain-specific challenges.

### 5. Curriculum & ABET Refinement

- **Refine Learning Outcomes:** Update and polish the ABET-aligned learning outcomes generated by the engine. *Note: This is contingent upon the stabilization of the output schema and label logic.*
- **Stakeholder Review:** Prepare findings, error analyses, and refined curriculum outputs for the upcoming review meeting with Dr. Lisa Abrams (CSG) and Dr. Asmita Mrumkar.
